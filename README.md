# Sinda Nexus

منظومة ذكية وقابلة للتكوين لإدارة المشاريع والملفات والتقارير.

## الحالة

هذا فرع تطوير لتقوية API. يتطلب كل مسار تحت `/api` رمز Bearer مضبوطًا في `API_TOKENS`؛ وإذا لم يُضبط أي رمز، تُغلق المسارات المحمية افتراضيًا وتعيد `503`. يظل `/health` عامًا ولا يعرض بيانات المشروع.

## المتطلبات والتشغيل

- Node.js 20 أو أحدث.
- تثبيت الاعتماديات: `npm install`.
- نسخ `.env.example` إلى `.env` وتغيير `API_TOKENS` إلى سر عشوائي طويل. مثال لتوليد قيمة: `openssl rand -hex 32`.
- تشغيل الاختبارات: `npm test`.
- تشغيل فحص الصياغة والاختبارات: `npm run check`.
- تشغيل الخدمة: `npm start`.

لا تضع قيمة حقيقية لـ `API_TOKENS` في المستودع أو السجلات. يمكن فصل الرموز المتعددة بفواصل، ويجب تمرير الرمز في ترويسة `Authorization: Bearer <token>`.

## الإعدادات

| المتغير | الافتراضي | الغرض |
|---|---|---|
| `HOST` | `127.0.0.1` | واجهة الاستماع |
| `PORT` | `3000` | منفذ HTTP |
| `API_TOKENS` | غير مضبوط | رموز الوصول؛ غيابها يغلق API |
| `DATA_FILE` | `./data/projects.json` | ملف تخزين بيانات المشاريع |
| `MAX_PROJECTS` | `1000` | الحد الأقصى لعدد المشاريع |
| `RATE_LIMIT_WINDOW_MS` | `60000` | نافذة تحديد المعدل بالمللي ثانية |
| `RATE_LIMIT_MAX` | `100` | الطلبات المسموح بها ضمن النافذة |

يمكن تمرير `:memory:` كخيار تخزين عند إنشاء التطبيق للاختبارات فقط. حد جسم JSON هو 100 KiB، ويُرفض الجسم الزائد برمز HTTP 413.

## حدود أمنية مهمة

- Bearer token هنا بوابة وصول مشتركة وليست نظام هوية مستخدمين كاملًا؛ لا توجد حتى الآن أدوار أو ملكية لكل مشروع أو تدوير رموز مدمج. استخدمه فقط في بيئة اختبار موثوقة، ولا تعرض الخدمة للإنترنت أو تضع بيانات حساسة فيها.
- التخزين الحالي ملف JSON محلي بكتابة مؤقتة ثم إعادة تسمية. هذا أنسب لعملية واحدة وتجارب محدودة فقط؛ ليس قاعدة بيانات معاملات، ولا يدعم بأمان عدة نسخ خدمة تكتب الملف نفسه. يلزم اعتماد قاعدة بيانات مناسبة قبل الاستخدام الإنتاجي.
- لا توجد حتى الآن سجلات تدقيق، أو نظام مستخدمين/صلاحيات تفصيلي، أو مسار رفع ملفات.
- ملف `package-lock.json` لم يُنشأ/يُتحقق منه في هذه البيئة؛ لذلك لا تعتبر الاعتماديات قابلة لإعادة البناء بشكل حتمي حتى يُولّد lockfile فعلي ويُراجع.
- لا دمج أو نشر ضمن هذا التغيير. يجب مراجعة نتائج الاختبارات والتدقيق وإعدادات الاستضافة يدويًا قبل أي إصدار.

## نقاط النهاية

- `GET /health` — فحص صحة عام لا يعرض بيانات.
- `GET /api/projects` — قائمة المشاريع (يتطلب Bearer token).
- `POST /api/projects` — إنشاء مشروع (يتطلب Bearer token).
- `GET /api/projects/:id` — تفاصيل مشروع (يتطلب Bearer token).
- `GET /api/reports/summary` — ملخص المشاريع (يتطلب Bearer token).
